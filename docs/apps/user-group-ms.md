# user-group-ms

> REST microservice that manages groups of users of an institution for a given product (create, update, suspend/activate, delete, membership).

| | |
|---|---|
| Path | `apps/user-group-ms` |
| Stack | Spring Boot 3.3.0 via `selc-starter-parent` 0.3.3 (`libs/selfcare-starter-parent/pom.xml`; the app POM references `0.3.1-SNAPSHOT`), Java 17, blocking (Spring MVC + Spring Data MongoDB) |
| Type | REST microservice |
| Tenants | Both: separate `-ar` and `-pnpg` deployments, plus tenant-aware data layer |
| Infra | `infra/resources/user-group-ms/` |

## Responsibilities

- CRUD and lifecycle (`ACTIVE`/`SUSPENDED`/`DELETED`) of user groups stored in `UserGroups`.
- Membership management, per group and in bulk by `parentInstitutionId` (used to keep "aggregator" groups in sync, see [user-cdc](user-cdc.md)).
- Consume `InstitutionUpdatedEvent` from the internal events Service Bus (topic `institution-events`, subscription `user-group-sub`) and rename the groups whose `parentInstitutionId` matches the updated institution ("Ente Aggregatore …"). Producer: [institution-cdc](institution-cdc.md).

## Architecture

Single Maven module, package `it.pagopa.selfcare.user_group`:

| Package | Content |
|---|---|
| `controller` | `UserGroupV1Controller` (`/v1/user-groups`) |
| `service` | `UserGroupService` / `UserGroupServiceImpl` (all Mongo reads/writes; applies the tenant filter) |
| `dao` | `UserGroupRepository` (Spring Data `MongoRepository`) |
| `model` | `UserGroupEntity` (`@Document("UserGroups")`, includes `tenantId`), DTOs, `UserGroupMapper` |
| `internalevents` | `InternalEvents` (Service Bus receiver from [selfcare-internal-events-sdk](../libs/selfcare-internal-events-sdk.md)) |
| `config` | `CoreConfig`, `WebConfig`, `SwaggerConfig`, `UserGroupSecurityConfig` (imports `SecurityConfig` from `selc-commons-web`) |
| `handler` | `UserGroupExceptionHandler` (`@RestControllerAdvice`, `ProblemDetail`) |
| `health` | `MongoReadinessIndicator` ([selfcare-sdk-health-spring](../libs/selfcare-sdk-health-spring.md)) |

## API

Spec: `apps/user-group-ms/src/main/docs/openapi.json` (generated by `SwaggerConfigTest`). All endpoints require a bearer JWT.

| Method | Path | Tags (APIM exposure) |
|---|---|---|
| `POST` | `/v1/user-groups` | — |
| `GET` | `/v1/user-groups` | `external-v2`, `external-pnpg`, `support`, `support-pnpg` |
| `GET` / `PUT` / `DELETE` | `/v1/user-groups/{id}` | `GET`: `external-v2` |
| `POST` | `/v1/user-groups/{id}/activate`, `/v1/user-groups/{id}/suspend` | — |
| `PUT` / `DELETE` | `/v1/user-groups/{id}/members/{memberId}` | `DELETE`: `support` |
| `DELETE` | `/v1/user-groups/members/{memberId}` | `support` |
| `PUT` / `DELETE` | `/v1/user-groups/members` (by `parentInstitutionId`) | `internal-v1` |

Not an application API in APIM: it is a backend of the external APIs defined in `infra/resources/_modules/apim_external_api/` (`apim.tf`: `external` v2, `external/internal`, `external/support`; `apim_pnpg.tf`: `external/pn-pg`, `external/pn-pg/support`), routed to `selc-<env>-user-group-ca` (and the PNPG equivalent).

## Data and messaging

| Resource | Usage |
|---|---|
| MongoDB database `selcUserGroup`, collection `UserGroups` | Read/write (database and connection chosen through the tenant registry) |
| Service Bus `selc-<env>-ar-internal-events`, topic `institution-events`, subscription `user-group-sub` | Consumes `InstitutionUpdatedEvent` (enabled only in AR stacks) |

Changes to `UserGroups` are streamed to Event Hub `sc-usergroups` by [user-group-cdc](user-group-cdc.md).

## Integrations

- Outbound REST clients: none.
- Callers and their spec copies: [dashboard-bff](dashboard-bff.md) (`apps/dashboard-bff/docs/openapi/user-group-docs.json`), [user-ms](user-ms.md) (`apps/user-ms/src/main/openapi/user_group_ms.json`), [user-cdc](user-cdc.md) and other external consumers through APIM `external/internal`.

## Configuration

From `src/main/resources/config/application.yml` and `core-config.properties`:

| Group | Env vars |
|---|---|
| Server / logging | `MS_USER_GROUP_SERVER_PORT`, `MS_USER_GROUP_LOG_LEVEL`, `ALLOWED_SORTING_PARAMETERS` |
| MongoDB (single-tenant fallback) | `MONGODB_CONNECTION_URI`, `MONGODB_NAME` |
| Tenant registry | `SELFCARE_TENANT_DATA_ISOLATION`, `TENANT_SUPPORTED_TENANTS`, `TENANT_DEFAULT`, `TENANT_STRICT_DATA_ISOLATION`, `TENANT_STORAGE_MANDATORY_KEYS`, `TENANT_MONGODB_ENABLED`, `TENANT_STORAGE_ENABLED` |
| Internal events | `INTERNALEVENTS_ENABLED`, `INTERNALEVENTS_CONNECTION_STRING`, `INTERNALEVENTS_NAMESPACE`, `INTERNALEVENTS_CLIENT_ID` |

Terraform sets, per domain, the registry JSON and the secrets it references (`MONGODB_CONNECTION_STRING_AR` / `JWT_PUBLIC_KEY_AR` or `..._PNPG`, from Key Vault `mongodb-connection-string` and `jwt-public-key`). The registry only contains env var names, never secrets (see the app README).

## Multitenancy

- **Tenant resolution**: the request tenant is taken from the `X-Tenant-Id` header by the JWT filter of `selc-commons-web` (duplicated headers are rejected) and stored in `TenantContext` (`selc-commons-tenant`, sources in `libs/selfcare-commons/`).
- **Resource selection**: MongoDB connection, database and JWT public key come from the tenant registry (`SELFCARE_TENANT_DATA_ISOLATION`). Each deployment currently registers only its own tenant (`AR` or `PNPG`).
- **Data isolation**: `UserGroupServiceImpl` stamps `tenantId` on writes and adds a `tenantId` criterion to every query; with `TENANT_STRICT_DATA_ISOLATION=false` documents without `tenantId` are also matched.
- See [../multitenancy.md](../multitenancy.md), [Step 2 architecture](../specs/MULTITENANT/Step_2/ARCHITECTURE.md), [Database identification](../specs/MULTITENANT/Step_2/Database_identification.md), [JWT key resolution](../specs/MULTITENANT/Step_2/JWT_Key_Resolution.md).

## Build, run and test

```bash
mvn -f apps/user-group-ms/pom.xml clean package
mvn -f apps/user-group-ms/pom.xml test
mvn -f apps/user-group-ms/pom.xml spring-boot:run
# regenerate src/main/docs/openapi.json
mvn -f apps/user-group-ms/pom.xml test -Dtest=SwaggerConfigTest -Dsurefire.failIfNoSpecifiedTests=false
# Cucumber integration tests (Docker required), as in CI
mvn --projects :user-group-ms --also-make test -Dtest=CucumberSuite -Dsurefire.failIfNoSpecifiedTests=false
mvn --projects :test-coverage --also-make verify -Puser-group-ms,report
```

Cucumber runner: `it.pagopa.selfcare.user_group.integration_test.CucumberSuite`, features in `src/test/resources/features/` (create, retrieve, update, members), glue includes `it.pagopa.selfcare.cucumber.utils` from [selfcare-cucumber-sdk](../libs/selfcare-cucumber-sdk.md). Report: `target/cucumber-report/cucumber.html`. Local stack: `apps/user-group-ms/docker-compose.yml`.

## Deployment

- Container Apps `*-user-group` (AR) and `*-pnpg-user-group` (PNPG), image `selfcare-user-group-ms`, stacks `dev|uat|prod-ar` and `dev|uat|prod-pnpg`.
- The same stacks provision the Cosmos MongoDB database `selcUserGroup` and collection `UserGroups` (modules `_modules/cosmosdb_database`, `_modules/cosmosdb_collection`).
- PR: `.github/workflows/pr_user_group_ms.yml`, `.github/workflows/pr_user_group_ms_infra.yml`; integration tests: `.github/workflows/integration_tests_user_group_ms.yml`.
- Release: `.github/workflows/trigger_release_user_group_ms.yml` → `release_app.yml` for `ar` and `pnpg`; DEV auto-release via `trigger_deploy_after_merge.yml`.
- APIM definitions: `infra/resources/_modules/apim_external_api/` (released by `release_apim.yml`).
