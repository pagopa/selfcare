# Onboarding CDC

The service watches onboarding changes and invokes the notification HTTP function
for events that must be propagated to downstream consumers.

## Onboarding Functions requester identity

Notification calls include `x-selfcare-uid: m2m:onboarding-cdc`. The stable
service identity is generated by the OpenAPI client contract and lets
onboarding-functions write a structured `userId` property for every invocation.

The client sends the Azure Function key, `X-Tenant-Id`, and the configured
`JWT_BEARER_TOKEN`. Before sending, it decodes the technical JWT and fails closed
when it is malformed, expired, not RS256, lacks `iss`/`uid`, or its `tenant_id`
does not match the resolved tenant. Signature and allowed-issuer verification are
still performed by onboarding-functions.

`JWT_BEARER_TOKEN` is an expiring Key Vault secret: rotate it before `exp` and
keep its signing key aligned with the target stack's public key. Each deployment
must remain tenant-specific; a token minted for AR cannot be reused by PNPG (or
vice versa).
